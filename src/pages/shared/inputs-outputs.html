Inputs & outputs

Containers and components talk to their parent the same way: data goes down through inputs, events come up as outputs.

Parent templateChild class
Inputnb-in:page-size="this.size"public pageSize = 10; receives a deep copy
Input by referencenb-in-ref:store="this.store"public store?: Store; receives the same object
Outputnb-event:saved="this.reload(data)"injects EventDispatcher and calls dispatch('saved', id), or assigns an @Eventer() property
  • Names are kebab-case in markup and camelCase in the class: nb-in:page-size sets pageSize.
  • An input is delivered only when it changes — a value deeply equal to the last one is skipped. Then the child runs a pass and its onInputsRefreshDone() hook.
  • nb-in copies with structuredClone: the child cannot touch the parent's data, and in-place edits in the parent still arrive. Functions, class instances, DOM nodes and anything else that cannot be cloned need nb-in-ref — where only assigning a new object updates the child.
  • Treat inputs as read-only in the child; change the data in the parent.
  • Output events do not bubble: only the direct parent hears them — dispatch again to go further up. Use kebab-case event names, because HTML lowercases nb-event:itemSaved.
