Configuration & security

Global options go into @AppRoot as an object. Here: W3C-valid attributes and an HTML sanitizer.

  • Unknown keys or wrong types make the whole object unrecognized, and it is ignored without a message.
  • The configuration cannot change once the first app root is bound.
  • @AppRoot arguments are recognized by type, like every decorator's. Unlike the others, it throws when given two selectors, two route templates or two configs.
  • W3C mode: nb-x becomes data-nb-x and : becomes --.
  • {{ }} is compiled at build time and still emits nb-value, which W3C mode ignores. Add "nubond": { "compliantWithW3CInterpolation": true } to package.json and it emits data-nb-value.

Shadow roots for all components: $GlobalShadowRootConfig

The default shadow root is not part of the global config — a shadowRootConfig key there makes the whole object unrecognized. Each component reads the default when its module is imported, before any code in index.ts runs, so set it in a module imported first:

  • A later call reaches only components imported after it, without a message. The last call wins.
  • A component's own shadowRootConfig replaces the default as a whole — fields are not merged.

What is sanitized

ContentSanitized?
nb-html valuesYes, when an htmlSanitizer is configured — otherwise written as is.
Templates and styles from a URL or a providerYes, with the configured sanitizer.
Inline templates and styles (incl. imported files)No — they are your source code.
nb-attr / nb-prop valuesNever — check href, src, srcdoc yourself.

The most specific sanitizer wins: a component or container config (@Component(html, css, { htmlSanitizer, styleSanitizer })), the last argument of $Template(name, html, sanitizer), $AdoptedStyle(name, css, sanitizer) and @Aspect(css, sanitizer), then the global config.

Several apps on one page

@AppRoot('#widget') binds to a selector (or an Element) instead of <body>, so nuBond can live next to another framework and take over a page piece by piece. The element must already be in the page; a root whose element is later removed is disposed automatically. All roots share one registry and one configuration — set it with $Config and $Route before the first root.
