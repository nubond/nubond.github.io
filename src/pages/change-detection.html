Change detection

nuBond updates the DOM in a pass: it re-evaluates the bindings of a template and writes what changed. A pass runs only when something triggers it.

A timer increments ticks ten times a second, yet the number only moves when a pass runs. Every button is an nb-event, so a click renders once; then watch what happens one second later.

  • A pass covers one template. A child re-renders when its inputs change; siblings and parents are not touched.
  • Passes are asynchronous and batched: ten triggers in one task produce one pass. Do not read the DOM right after changing state.
  • @Detector() compares deeply: assign a new object (this.cfg = {...this.cfg, x: 2}), do not mutate it.
  • A container or component hidden by nb-if / nb-switch is paused; a detect() requested meanwhile runs once it is shown again.
  • An app root whose element is removed from the page is disposed on its next change-detection request.

Telling the parent: @Eventer()

Assigning an @Eventer() property dispatches a custom event named after it (seconds; selectedItem → selected-item) with the value as data. @Eventer('tick') picks the name. A value deeply equal to the previous one is not dispatched again, and an initial value is announced once after the first pass.

@Detector() and @Eventer() work on plain fields declared in the class itself — not on get/set accessors and not on fields inherited from a base class.

Strategies

Optimistic (default) runs one pass per trigger. Pessimistic repeats the pass while bindings keep changing (up to 10 times) — for templates whose bindings feed each other.

Never assign a @Detector() property from a template expression: every write schedules another pass. After about 20 the detector is disabled for good, with an error in the console.
