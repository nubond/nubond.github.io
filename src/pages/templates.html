Templates & projection

Reuse markup: register a snippet once with $Template, or pass markup into a container or component with projection.

Global templates

  • $Template(name, html) registers a fragment; nb-template="@name" puts it inside an element.
  • The fragment binds in the scope it lands in — here each row's item.
  • A template must be registered before an element using it is built. $Template returns the name, so register it in the array of the @AppRoot or @Container that needs it: @Container(html, [$Template('price-tag', tagHtml)]). Not in a @Component — its array lists adopted styles, so the name would be taken as a style. For a component, register the template in its parent container or the app root.

Projection

WhereAttributeDoes
usernb-projection="@name"Marks content for the slot @name; without a value, for the default slot.
templatenb-project-to="@name"The content replaces the slot element's children.
templatenb-project-instead="@name"The content replaces the slot element itself.
  • Slot names are matched as written, so use the same text on both sides.
  • A slot that receives nothing keeps its own content — a built-in default.
  • Only one element may target the default slot; wrap several in one element.
  • Works the same for containers, components and $Templates.

Projected markup is copied into the receiving template and bound there: this is the card, not the page that wrote the markup. Hand data to the card through nb-in.
